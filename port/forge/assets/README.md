# OpenCE : Faber — Forge

Forge is OpenCE : Faber's in-engine world editor and co-op sandbox: the 3D
Monitor, the spawn palette, runtime tag cloning from other maps, AI placement,
and export to a standard Custom Edition `.map`. This document describes how it
is laid out in the repository and how it runs.

> [!IMPORTANT]
> Forge is built into the **Windows build only**. `tools/windows_build.py`
> compiles `port/forge/src/*.c` and packages `Faber_data/`; the Linux, Android
> and web builds do not compile Forge, and get a no-Forge fallback for the two
> names the shared code asks for (`port/linux/game/forge_fallbacks.c`). Forge's
> keyboard input uses Win32's `GetAsyncKeyState`, so porting it means replacing
> that with the engine's own input first.

## Repository layout

| Path | Contents |
| --- | --- |
| `port/forge/include/forge_engine.h` | Shared Forge declarations; `FORGE_VERSION_STRING` (read by `tools/linux_build.py` for the build number) and `FORGE_NETWORK_VERSION` |
| `port/forge/include/forge_cache_builder.h` | The tag cloner, cache builder, custom tag extractor and map exporter |
| `port/forge/include/forge_net_override.h` | Force-included (Windows build) into the network units so that `HALO_PORT_NETWORK_VERSION` reads `forge_get_network_version()` |
| `port/forge/src/forge_3d_mode.c` | The 3D Monitor, the physics beam (grab, move, rotate, snap, clone, lock, delete), the 3D preview and the spawn menu |
| `port/forge/src/forge_runtime_tags.c` | The first-use local tag cache builder, the runtime `.ftag` / bitmap loader, the embedded marker tags, `g_forge_session_enabled` and `forge_get_network_version()` |
| `port/forge/src/forge_cache_builder.c` | Schema-driven tag cloning, bitmap and sound internalisation, the credits writer, and the `.map` exporter |
| `port/forge/src/forge_network.c` | Forge lobby isolation and replication of placed objects |
| `port/forge/src/forge_hooks.c` | Engine and SDL3 hooks, map path redirection |
| `port/forge/src/forge_ai.c` | Placing the engine's own AI actors |
| `port/forge/src/forge_marker_ftags_embed.h` | The gametype marker `.ftag` bundles (zlib-compressed), embedded in the executable |
| `port/forge/tools/forge_asset_compiler.c` | Stand-alone CLI cache compiler and validator |
| `port/forge/assets/` | What `ninja windows` copies into `Faber_data/`: `ui/`, `cached_tags/` (the markers and `xbox_catalog.txt`), `credits.md` |

Some Faber features that Forge shares the menus with live in
`port/linux/game/` and are compiled on every build: Firefight
(`firefight*.c`), the firing range, the tag editor and tag injector, Theater
(`network_replay*.c`) and the server director. The Forge menu screens are
generated by `tools/port_settings.py` (`_forge_screens`).

The Windows build also renames a few symbols in specific objects
(`FORGE_OBJCOPY_REDEFINES` in `tools/windows_build.py`) so that Forge can wrap
map listing and file access.

## Runtime layout

Everything Faber-specific lives in `Faber_data/` beside the executable; the
shared OpenCE files (`maps/`, `custom_maps/`, `saves/`, `config.toml`) are
read where they are.

```text
<game folder>/
├── OpenCE - Faber.exe        # same build as halo.exe
├── halo.exe
├── SDL3.dll
├── maps/                     # user-provided
├── custom_maps/              # user-provided; Forge exports land here too
└── Faber_data/
    ├── credits.md            # creator attribution for every extracted tag
    ├── ui/                   # Forge panels
    ├── custom_bmp/           # optional <map>.bmp thumbnails to embed on export
    ├── custom_tags/          # tags added through TAG OPTIONS
    └── cached_tags/
        ├── markers/          # gametype markers (also embedded in the exe)
        ├── xbox_catalog.txt
        ├── catalog.txt       # built on first use
        ├── custom_catalog.txt
        └── <class>/          # extracted .ftag bundles, built on first use
```

Older installs used `OpenCE Forge/` and `forge_maps/<name>/`; Forge still
reads those paths, and removes stale `forge_maps/<name>/` copies when a map of
the same name is exported again.

## First-use local tag cache

No `.map` files or tag caches extracted from them are distributed. On first
use, Forge indexes the user's own `maps/` and `custom_maps/` and writes
`.ftag` bundles and catalogues into `Faber_data/cached_tags/`, logging the
source map of every root tag in `Faber_data/credits.md`. More tags can be added
from any custom `.map` through **Forge → TAG OPTIONS**.

## Saving a map

**F5** exports the edited map to `custom_maps/<name>.map`, a stock Custom
Edition cache with the placed objects, their tags and AI encounters baked in.
The 140×114 preview thumbnail and the description are stored inside the
`.map`; the thumbnail is drawn from the base map's BSP and the placed objects,
or taken from `Faber_data/custom_bmp/<name>.bmp` if present. Standard OpenCE
can host and share the exported map.

## Networking

Forge sessions use `FORGE_NETWORK_VERSION` while `g_forge_session_enabled` is
set, and OpenCE's own `HALO_PORT_NETWORK_VERSION` otherwise, so Forge lobbies
and stock games never mix, and an upstream protocol bump does not stop Faber
joining stock games. Raise `FORGE_NETWORK_VERSION` with any change to what
Forge clients send each other.
